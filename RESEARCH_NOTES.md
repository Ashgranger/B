## 1. Analysis of the User's Server Errors & Root Causes

### Error A: `{"error":{"code":30001,"message":"Invalid Type"}}`
* **Root Cause**:
  Lighter's WebSocket server at `wss://api.rh.lighter.xyz/stream` strictly requires all mutations and transaction submissions to have top-level `"type": "jsonapi/sendtx"` or `"type": "jsonapi/sendtxbatch"`.
  In the previous version, `exchange.py` sent `{"type": "post", "id": 1, ...}` over WebSocket.
  Lighter rejected this frame with code `30001` (`AppErrWebsocketInvalidType`).
* **Fix Implemented**:
  In `exchange.py`, all order placements, cancellations, modifications, and Dead Man's Switch (DMS) scheduleCancel transactions are wrapped strictly as:
  ```json
  {
    "type": "jsonapi/sendtx",
    "data": {
      "id": "1",
      "tx_type": 14,
      "tx_info": "{...}"
    }
  }
  ```
  Batch transactions use `"type": "jsonapi/sendtxbatch"` with `"tx_types"` and `"tx_infos"`.

---

### Error B: `{"error":{"code":30005,"message":"Invalid Channel"}}` (Repeated 6 Times)
* **Root Cause**:
  In `bot.py`, 6 legacy channel subscriptions (`"bbo"`, `"l2Orderbook"`, `"trades"`, `"orders"`, `"userFills"`, `"positions"`) were being sent unconditionally on WebSocket connect.
  These channels do not exist on Lighter. The Lighter sequencer rejected all 6 with code `30005` (`AppErrWebsocketInvalidChannel`).
* **Fix Implemented**:
  Guarded simulator channels so they are only subscribed in mock/offline mode (`hasattr(self.ex.ws, "_post")`).
  On live connections to `wss://api.rh.lighter.xyz/stream`, the bot subscribes exclusively to valid Lighter channels:
  1. `order_book/{market_id}`: Differential and snapshot L2 depth.
  2. `ticker/{market_id}`: Real-time Best Bid & Offer (BBO) touch.
  3. `trade/{market_id}`: Real-time trade fills with buyer/seller attribution.
  4. `market_stats/{market_id}`: Live mark price, index price, funding rates.
  5. `user_stats/{account_index}`: Margin, collateral, and portfolio value.
  6. `account_orders/{market_id}/{account_index}`: Private order lifecycle stream.
  7. `account_market/{market_id}/{account_index}`: Private position and balance stream.

---

### Error C: `{"error":{"code":20013,"message":"invalid auth: account_orders:0"}}` & `account_market:0:29522`
* **Root Cause**:
  Lighter's WebSocket server validates authentication tokens for private channels using Poseidon-Schnorr zero-knowledge cryptographic signatures generated by Lighter's native C/WASM library (`lighter_signer_linux_amd64.so`).
  A custom HMAC/Ed25519 token generated in pure Python does not match Lighter's verification circuit, causing the server to reject the auth token with code `20013`.
* **Fixes Implemented**:
  1. **Native SignerClient Integration**: In `signer.py`, when `lighter-sdk` (`lighter`) is installed in the Python environment, `Signer` directly delegates auth token generation and transaction signing to `lighter.SignerClient(url, api_private_keys, account_index)` and `client.create_auth_token_with_expiry(deadline=28800, api_key_index=...)`.
  2. **Public Trade Fill Attribution**: Even if private stream auth fails, the bot now monitors the public `trade/{market_id}` stream in real time. Because every trade payload includes `ask_account_id` and `bid_account_id`, the bot detects its own fills whenever `ask_account_id == self.account_index` or `bid_account_id == self.account_index`.

---

### Error D: `market NVDA-USD not directly matched in orderBookDetails; using default profile`
* **Root Cause**:
  Lighter formats market tickers differently depending on whether they are queried by display name or base symbol (e.g. `NVDA`, `NVDA-USD`, `NVDA_USD`, `NVDA/USDC`).
  When `NVDA-USD` was not matched exactly against the raw symbol string, `exchange.py` fell back to market index `0` (which is ETH-USD). This caused the bot to quote at $2,570 (the price of ETH) instead of $120 (the price of NVDA).
* **Fix Implemented**:
  Added `_norm_symbol(s)` in `exchange.py` which strips currency suffixes (`USD`, `USDC`, `USDT`) and delimiters (`/`, `-`, `_`).
  Both `NVDA-USD`, `NVDA_USD`, and `NVDA` normalize to `NVDA` and match seamlessly.
  Added diagnostic logging that prints all discovered markets on Robinhood Lighter upon startup (`Discovered N markets on rh_mainnet: [...]`).

## 2. Robinhood Lighter Protocol Specification

### Endpoints
* **REST API**: `https://api.rh.lighter.xyz`
* **WebSocket Stream**: `wss://api.rh.lighter.xyz/stream`
* **Read-only Stream**: `wss://api.rh.lighter.xyz/stream?readonly=true`
* **Chain ID**: `4663` (Robinhood Chain Arbitrum L2)

### Transaction Types
* `TxTypeL2ChangePubKey = 8`: Register API key.
* `TxTypeL2CreateOrder = 14`: Limit, market, stop orders.
* `TxTypeL2CancelOrder = 15`: Single order cancellation.
* `TxTypeL2CancelAllOrders = 16`: Batch cancel / Dead Man's Switch.
* `TxTypeL2ModifyOrder = 17`: Order modification.

### Time In Force (TIF)
* `0`: Immediate-or-Cancel (`IOC`) — requires `orderExpiry = 0`.
* `1`: Good-till-Time (`GTT`) — millisecond timestamp 5 min to 30 days ahead.
* `2`: Post-Only (`ALO`) — maker-only; rejected if crossing.

### Dead Man's Switch
Uses `TxTypeL2CancelAllOrders` (`16`) with `TimeInForce = 1` (`CANCEL_ALL_SCHEDULED`) and deadline millisecond timestamp.
Disarm uses `TimeInForce = 2` (`CANCEL_ALL_ABORT`).
Refreshed automatically every `DMS_TTL_S / 3` seconds.
